# アイディア発明レポート

> 参照：`docs/ideation/customer_insights.md`  
> 解決する核心課題：孤立した罪悪感の解消 / 他者の怠惰の不可視性 / 開き直りへの心理的ハードル

---

## 1. 参考事例の収集

| # | サービス名 | 概要 | 技術的特徴 | ビジネス的特徴 |
|---|-----------|------|-----------|--------------|
| 1 | **Snapchat Streaks** | 毎日連続でメッセージを送ることで「炎」カウンターが増える。途切れたくないという心理で習慣化を促す | プッシュ通知・ゲーミフィケーション | 継続率向上によるDAU最大化。広告収益モデル |
| 2 | **Pokémon GO** | GPS連動でリアル空間にポケモンを出現させ、近くにいるユーザーとレイドバトルができる | GPS・AR・リアルタイム近接検知 | 位置情報×集合行動で課金誘導。店舗スポンサーモデル |
| 3 | **たまごっち（Tamagotchi）** | ホーム画面（物理デバイス）で生きているキャラを育てる。放置すると死ぬという罪悪感で継続させる | シンプルな状態管理・通知 | ハードウェア販売。キャラIPのブランド化 |
| 4 | **BeReal** | 1日1回ランダムな時間にフロント・バックカメラ同時撮影を促す。「演じない日常」の可視化 | プッシュ通知・同期撮影 | 「リアルな自分」という価値観の商品化。広告モデル |
| 5 | **Mastodon/分散SNS** | 地域・テーマごとのサーバーで「近い属性の人だけ」と繋がれる。アルゴリズムなしの等身大の繋がり | 分散型サーバー・ActivityPub | 小規模コミュニティの熱量を活かした投げ銭・課金モデル |

## 2. アイディアの発明

### アイディア A：「ダメウィジェット」（本命案）

**Pokémon GO の近接集合 × たまごっちのキャラ育成 × BeReal の「演じない可視化」**

| 項目 | 内容 |
|------|------|
| アイディア名 | **ダメウィジェット**（仮称：スロスくん / Sloth Sync） |
| 解決する課題 | 孤立した罪悪感の解消・他者の怠惰の不可視性 |
| 技術的アプローチ | GPS近接検知（Bluetooth + GPS）でタップ時に半径数km以内のアクティブユーザー数を取得。ウィジェットAPIでキャラが「増殖・共鳴」アニメーション |
| 期待される効果 | 「今この瞬間、近くに○○人がだらけている」という事実の可視化により、罪悪感を即時解消。毎日複数回のタップ習慣（DAU向上） |
| 実装難易度 | 中（GPS+ウィジェットは既存iOS/Android APIで実現可能。バックエンドはシンプルな位置情報集約サーバーで十分） |

---

### アイディア B：「怠惰ランキング」

**Snapchat Streaks のゲーミフィケーション × 逆ランキング設計**

| 項目 | 内容 |
|------|------|
| アイディア名 | **怠惰ランキング**（最もだらけた時間を競う逆生産性アプリ） |
| 解決する課題 | 開き直りへの心理的ハードル・孤立した罪悪感 |
| 技術的アプローチ | スマホの加速度センサー・画面タッチ頻度から「活動しなさ度」を算出。地域・時間帯別ランキングを生成 |
| 期待される効果 | 「怠けることが実績になる」という逆転設計により、完全なオフへの移行を後押し。週次レポートで「先週の怠惰スコア」を表示 |
| 実装難易度 | 中〜高（センサーデータの解釈にノイズ処理が必要。「怠惰度」の定義が難しい） |

---

### アイディア C：「ぬるま湯ラジオ」

**Mastodon の属性コミュニティ × BeReal の「今この瞬間」× 音声メディア**

| 項目 | 内容 |
|------|------|
| アイディア名 | **ぬるま湯ラジオ**（だらけている人だけがリアルタイムで繋がれる音声空間） |
| 解決する課題 | 孤立した罪悪感・開き直りへの心理的ハードル |
| 技術的アプローチ | 「今だらけている」と申告したユーザーだけが入れるライブ音声ルーム。BGMと「誰かがいる音」だけを流し、孤独感を解消 |
| 期待される効果 | 「同じ時間にだらけている人と繋がっている感覚」によるセッション継続。孤独な怠惰を「共同怠惰」に変換 |
| 実装難易度 | 中（WebRTCベースの音声配信。コンテンツモデレーションが課題） |

## 3. 最有望案の選択

### 選択：**アイディア A「ダメウィジェット」**

| 評価軸 | A（ダメウィジェット） | B（怠惰ランキング） | C（ぬるま湯ラジオ） |
|--------|---------------------|-------------------|-------------------|
| 顧客インパクト | ◎ タップ一つで即時解消 | ○ 達成感はあるが手間がある | ○ 深い体験だが能動的参加が必要 |
| 実装難易度 | ○ 中程度・既存API活用可 | △ センサー解釈が複雑 | ○ 中程度だがモデレーション課題 |
| 独自性 | ◎ GPS×キャラ増殖×ウィジェットの組み合わせは新規 | △ 逆ゲーミフィケーションは前例あり | △ 音声SNSは競合多数 |
| 依存性（ダメにする力） | ◎ ウィジェット常駐でアプリ不要の超低摩擦 | ○ ランキングへの執着で継続 | ○ セッション継続するが離脱もしやすい |

**選択理由：**

「アプリを開かなくていい」というゼロ摩擦設計が他の案と決定的に異なる。ウィジェットは常に視野に入り、スマホを使う度にキャラの存在を感知できる。「タップ一つで近くの同志を検知する」というインタラクションは、課題1・2を同時に解決しながら、行動コストをほぼゼロに抑える。ハッカソンの評価軸「人をダメにする力」においても、最も強力な依存メカニズムを持つ。
