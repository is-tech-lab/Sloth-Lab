# Ideas — Refactor the World

## 1. 参考事例（類似課題の解決事例5選）

| # | サービス名 | 概要 | 技術的特徴 | ビジネス的特徴 | RTWとの類似点 | RTWとの決定的な違い |
|---|-----------|------|-----------|--------------|------------|-----------------|
| 1 | **Fix My Street**（日本版あり） | 街の問題（穴・落書き・壊れた設備等）をスマホで撮影・投稿→自治体へ自動振り分け。担当者がチェックして対応 | 位置情報＋画像添付。AI未使用。市民参加型インフラ報告の先駆け | 公共セクター向けSaaS。市民の問題発見行動を行政へ直結 | 「現実を写真で撮り、社会に向けて投稿する」行動モデルが最も近い | **マイナス→ゼロ**（壊れたものを直す）。速度遅い（行政対応は数週間〜数ヶ月）。創造性なし（「元通りにして」しか言えない）。RTWは**ゼロ→プラス**（機能しているものをより良く変える）、実現可能性度外視の創造的ビジョン |
| 2 | **RoomGPT / Reimagine Home** | 部屋の写真をアップロードすると、AIが別スタイルにリデザインした画像を即座に生成 | Stable Diffusion + ControlNet（画像構造を維持しながら再生成） | B2C SaaS。デザインインスピレーション市場。フリーミアム | 「写真→AIが理想の姿に変換→ビジュアルで見せる」体験イメージが近い | **用途が部屋限定**、かつ「現実的なリデザイン」が前提。RTWはカメラで写したあらゆるものが対象で、実現可能性は度外視した「ぶっ壊した理想」を生成する |
| 3 | **Canva Magic Studio** | 既存デザインをテキスト指示で即座にリデザイン。「もっとモダンに」等の抽象指示が使える | GPT-4V + Canva独自モデル。ワンクリックリデザイン | B2C + B2B。クリエイティブのコモディティ化 | 「テキスト1つで即変換」という即時性とUXの参考 | 既存デザインファイルを操作するツールであり、現実世界を対象としない |
| 4 | **Pika Labs / Runway** | 静止画→動画生成。before/afterを動的に表現 | Video diffusion model | クリエイター向けB2C | 生成コンテンツをSNSでシェアするビジョンが近い | 動画クリエイター向けの制作ツール。社会課題やSNS議論との連携がない |
| 5 | **DALL-E + GPT-4V（OpenAI）** | 画像を入力として認識し、テキストで改善提案＋改善後の画像を生成 | GPT-4V + DALL-E 3のパイプライン | API課金モデル。アプリ組み込みプラットフォーム | RTWの技術コアそのもの（コンポーネントとして活用） | 単体のAPIであり、SNS・コミュニティ・企業連携の仕組みがない |

## 2. 発明したアイディア3案

### Case A：「即座ビジョナリー」（メインコンセプト）
**= RoomGPTの「瞬時変換体験」× Fix My Streetの「現実投稿モデル」× SNSの「社会承認」× 企業データ連携**

| 項目 | 内容 |
|------|------|
| アイディア名 | Refactor the World（RTW） |
| 解決する課題 | 怠惰（行動コストゼロで潜在創造性を引き出す）＋ 傲慢（創造的ビジョンを企業へ届けるルートを作る）＋ 短期（遭遇の瞬間にエンゲージメントを捕捉する） |
| 対象スコープ | **何でも**。街・料理・プロダクト・空間・乗り物・看板など、カメラで写せるものすべて。「壊れているもの」ではなく「今はそれなりに機能しているがもっとよくなれるもの」が主対象 |
| 創造性の方針 | **実現可能性は度外視**。ユーザーがその瞬間ふと思い浮かべた理想形をAIが生成する。「現実的にどう直すか」ではなく「もし自分が設計し直したら」の視覚化 |
| 技術的アプローチ | アプリ内カメラ → GPT-4V（現状解析・変換方向の把握）→ DALL-E 3 / Stable Diffusion（理想状態の画像生成）→ SNSエンジン（投稿・評価） |
| 期待される効果 | 変換時間：ゼロ（アプリ内で完結、即時生成）、企業へのデータ：今まで取れなかった「ゼロ→プラス」の創造的インサイト群 |
| 実装難易度 | 中（AI API統合は既存技術で可能。差別化はSNS設計・企業データ販売の仕組み・コミュニティ形成） |

**UXフロー：**
1. **Capture**：アプリを開いてカメラで気になったものを写す（例：駅のホーム、昼食の料理、街の看板）
2. **AI Refactor**：アプリ内でその場でぶっ壊し、自分がイメージする理想の姿をAIが即座に生成（実現可能性は問わない）
3. **Social Commit**：生成されたビジョンをSNSに投稿。コミュニティから「いいね / PR（改善提案） / スタンプ」で評価される
4. **Real Deployment**：支持の高いビジョンを企業が「日々の創造的インサイト」として購入→実装が進む様子をビルドログで監視

**Fix My Streetとの本質的な違い：**

| 比較軸 | Fix My Street | Refactor the World |
|--------|--------------|-------------------|
| 方向性 | マイナス → ゼロ（壊れたものを直す） | ゼロ → プラス（機能しているものをより良く変える） |
| 速度 | 遅い（行政が動くまで数週間〜数ヶ月） | 即時（アプリ内で変換、その場でSNS投稿） |
| 創造性 | なし（「元通りにして」という要求しか出せない） | あり（実現可能性を度外視した創造的ビジョン） |
| 連携先 | 行政・自治体 | 企業（建設・外食・製造・小売など民間全般） |
| ユーザー動機 | 義務感・市民的責任 | 快楽・承認欲求・優越感 |

### Case B：「インフラ・プレビュー」（B2B特化版）
**= RoomGPT × Canva × Fix My Street を都市計画・インフラ企業向けに特化**

| 項目 | 内容 |
|------|------|
| アイディア名 | CityDraft |
| 解決する課題 | 課題2（影響力の断絶）：市民の声を建設・行政に直接届ける |
| 技術的アプローチ | 3D空間再構成（NeRF/Gaussian Splatting）+ 生成AI。現地写真から3Dモデルを生成し、改善案を3D空間上で可視化 |
| 期待される効果 | 市民参加型の都市設計フィードバックループ。企業は「どこが不満か」をリアルタイム把握 |
| 実装難易度 | 高（3D再構成技術の精度・速度が課題。モバイルで動かすには2〜3年かかる） |

### Case C：「ソーシャル・リファクター・エンジン」（コミュニティ特化版）
**= GitHub × X（Twitter）× DALL-E を「現実のIssueトラッカー」として設計**

| 項目 | 内容 |
|------|------|
| アイディア名 | IRL（In Real Life）GitHub |
| 解決する課題 | 課題2（影響力の断絶）：GitHubのIssue→PR→Mergeモデルを現実世界に適用 |
| 技術的アプローチ | 生成AI画像生成 + ソーシャルグラフ + 問題追跡システム。「Issue」は現実の問題、「PR」は改善案 |
| 期待される効果 | コミュニティによる問題の民主的解決。ナレッジコモンズ化 |
| 実装難易度 | 中（GitHubライクな設計は参考事例豊富。ただしコミュニティ形成が最大の課題） |

## 3. 最有望案の選択

### 選択：**Case A — Refactor the World（RTW）**

| 評価軸 | Case A | Case B | Case C |
|--------|--------|--------|--------|
| 顧客インパクト | 🔴 高（全3課題を解決） | 🟡 中（課題2のみ） | 🟡 中（課題2中心） |
| 実装難易度 | 🟡 中 | 🔴 高 | 🟡 中 |
| 独自性 | 🟢 高（心理変質モデルが差別化） | 🟡 中 | 🟡 中 |
| 収益化可能性 | 🟢 高（B2C＋企業データ販売のデュアルモデル） | 🟡 中 | 🟡 中 |
| **総合** | **🏆 最有望** | 次点 | 次点 |

**選択理由：**
- 3つの課題すべてを「1つのUXフロー」で解決できる唯一の案
- 「心理変質」というマーケティング哲学が既存SNSとの差別化要因になる
- データ販売モデル（企業への市場インサイト提供）により、ユーザーを無料にしながら収益化できる
- 既存技術（GPT-4V + 画像生成AI）の組み合わせで、6〜12ヶ月でMVP構築が現実的
