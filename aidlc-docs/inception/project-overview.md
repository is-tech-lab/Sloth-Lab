# Project Overview — Refactor the World

## プロジェクトビジョン

**「世界はバグだらけだ。君が書き換えろ。」**

日常の何気ない風景を「もっとこうなればいいのに」に変える創造的衝動を、AIが即座に形にする。そのビジョンは企業に直接届き、採用されれば現実が変わる——「アーキテクトは動かない」が成立する世界を作る。

**方向性：ゼロ→プラス**（壊れたものを直すのではなく、機能しているものをより良く変える）

---

## コアコンセプト

### 3つの心理変質モデル

人間の弱さ（怠惰・短期・傲慢）が日常に生み出す事象を、RTWのエンゲージメントエンジンとして活用する。

| 弱さ | 日常での出現 | RTWがもたらす変質 | 企業にとっての価値 |
|-----|------------|----------------|----------------|
| **怠惰** | 問題に気づいても行動しない。潜在インサイトが表に出てこない | 「撮るだけ」の行動コストゼロ設計で潜在創造性を引き出す | 従来調査では取れなかった「沈黙の多数派」のビジョンデータが取得できる |
| **短期** | 今この瞬間の刺激しか受け付けない。エンゲージメントのピークが一瞬で消える | 即時AI生成・即時ポイント付与でピークを逃さず捕捉する | 問題遭遇の瞬間のリアルな創造的衝動データが取得できる |
| **傲慢** | 「自分のアイデアは優れている」という確信があるが、企業に届くルートがない | 企業からの直接注目・採用報酬・PoCへの招待でその確信に応える | 自己評価の高い層の改善ビジョンをクラウドソーシング型R&Dとして活用できる |

### UXフロー

```
Capture（捉える）
    ↓
  アプリを開いてカメラで撮影
  壊れていなくていい。「なんとなく惜しい」「俺ならこうする」で十分

AI Refactor（書き換える）
    ↓
  アプリ内で即座に理想画像を生成（アプリ完結）
  実現可能性は度外視。自分が頭の中で描いた理想の姿

Social Commit（RTWに放つ）
    ↓
  RTWフィードに投稿 → ポイント付与
  コミュニティの いいね / PR / スタンプ で評価
  企業ダッシュボードにも表示 → 「企業が注目中」通知

Real Deployment（現実が変わる）
    ↓
  スポンサー課題への採用 or 企業がビジョンを実装
  採用報酬（ポイント換金）
  PoC招待：自分が描いた理想を実際に試す
  ビルドログで実装進捗を追跡
```

## ターゲットユーザー

### プライマリ：「アーキテクト気質の不満族」
- **年齢**：25〜35歳
- **属性**：都市生活者、IT系・クリエイター系職種
- **特徴**：「思うことはあるが動かない」。日常の何気ないものに創造的衝動を持つ
- **動機**：即時ポイント報酬 × 企業から注目される体験 × 自分のアイデアが現実になる実感

### セカンダリ：「即席クリエイター」
- **年齢**：18〜24歳（MARCH以上の学生等）
- **属性**：SNSネイティブ、承認欲求が高い意識高い系
- **特徴**：バズより「自分の審美眼が企業に認められる」体験を求める

### 企業クライアント（B2B）
- 外食・小売・製品メーカー・建設・交通・ファッションなど民間企業全般
- 欲しいもの：「どうなってほしいか」の視覚的ビジョンデータ（X/Instagramでは取れない）
- 使い方：インサイト購入 / スポンサー課題出題 / PoC参加者のマッチング

## コアバリュー

1. **即時性**：撮影→AI生成→投稿→ポイント付与がアプリ内で完結。待つことを設計しない
2. **影響力の実感**：X/Instagramでは変わらなかった現実が、RTWでは採用→実装→ビルドログで変わっていく
3. **優越感の正当化**：「批評家」「文句屋」ではなく「企業が注目するアーキテクト」として自己定義できる場
4. **仮説と検証の一貫ループ**：ビジョンを描いた人がそのままPoC参加者になる。RTWにしかできない構造
5. **自己強化フライホイール**：使うほどAI精度が上がり→生成画像が魅力的になり→投稿が増え→企業データの価値が上がる

## X / Instagram との差別化

| 比較軸 | X / Instagram | RTW |
|--------|--------------|-----|
| ビジョンの生成 | テキスト・写真のみ | **AIが理想画像を即座に生成** |
| データ構造 | 現状への反応（単方向） | **before/afterペア**（改善意図が構造化されている） |
| ユーザーへの報酬 | なし（プラットフォームが利益を得る） | **ポイント・採用報酬** |
| 企業との関係 | 一方通行 | **スポンサー課題・直接コメント・PoC招待** |
| PoC | 投稿者とテスターが紐付かない | **ビジョン投稿者=PoC参加者**として直接招待できる |
