## 機能要件

### FR-001: 投稿機能
- ユーザーがテキストで「仕事じゃないけど」の行動を投稿できる
- 投稿前にAIフィルタリングを通過する
- フィルタリングに引っかかった場合は「その投稿はここでは使えません」旨のフィードバックを返す

### FR-002: AIフィルタリング
- Claude APIを使用して投稿内容を判定する
- 以下のカテゴリをフィルタリングで除外する：
  - 仕事の成果・昇進・業績報告
  - 旅行・観光・充実した休暇
  - スポーツ大会の結果・自己啓発の成果
- 上記以外の「仕事じゃないけど」行動は通過させる

### FR-003: AIコメント機能（スタンプ機能に代替）
- 投稿がフィルタリングを通過した直後、Claude APIが称賛コメントを自動生成する
- コメントは偉人の名言・研究論文・心理学的知見のいずれかを引用した形式にする
  - 例：「ハーバードの研究によると、小さな親切の積み重ねが精神的幸福に最も寄与するとされています。あなたは今日それを実践しました。」
- コメントは投稿とセットでDBに保存し、タイムライン・自分の投稿一覧に表示する
- スタンプ・いいね・リアクション機能は一切設けない（比較・承認欲求が生まれるため）

### FR-004: タイムライン
- 全ユーザーのフィルタリング済み投稿を時系列（新しい順）で一覧表示する
- フォロワー・フォロー関係なく全投稿が表示される
- フォロワー数・いいね数・ランキングは一切表示しない

### FR-005: 過去投稿一覧
- 自分のこれまでの投稿履歴を一覧で確認できる
- 投稿へのスタンプ数が確認できる

---

## PoC MVPから除外する機能

| 機能 | 理由 |
|------|------|
| SNSログイン（Google等） | 後フェーズで追加 |
| フォロー・フォロワー機能 | コアコンセプトに不要 |
| スタンプ・いいね機能 | 比較・承認欲求が生まれるためAIコメントに代替 |
| プレミアムプラン | 収益化機能（後フェーズ） |
| toBデータ販売機能 | 後フェーズ |
| プッシュ通知 | PoC不要 |

## 非機能要件

### NFR-001: パフォーマンス
- AIフィルタリング（Claude API）のレスポンスタイム: 5秒以内（PoC許容値）
- タイムライン表示: 初回ロード3秒以内（PoC許容値）

### NFR-002: セキュリティ
- **スキップ**（PoC・プロトタイプのため）

### NFR-003: テスト
- プロパティベーステスト: **スキップ**（PoC・シンプルなCRUDのため）
- 基本的な動作確認レベルのテストを実施

### NFR-004: デプロイ
- AWS上にデプロイ（Amplify or EC2 + DynamoDB）
- ローカル開発環境での動作確認が可能

## データモデル（概要）

### Post（投稿）
| フィールド | 型 | 説明 |
|-----------|-----|------|
| postId | String (PK) | 投稿ID |
| content | String | 投稿本文 |
| authorId | String | 投稿者ID（PoC: 固定値または任意文字列） |
| createdAt | String (ISO) | 投稿日時 |
| stamps | Map | スタンプ種別ごとのユーザーIDリスト |

### FilterResult（フィルタリング結果）
| フィールド | 型 | 説明 |
|-----------|-----|------|
| allowed | Boolean | 通過/除外 |
| reason | String | 除外理由（ユーザーへのフィードバック用） |

## ユーザーシナリオ（主要）

### シナリオ1: 投稿する
1. ユーザーがテキストを入力して投稿ボタンを押す
2. Claude APIがフィルタリング判定を行う
3. 通過 → タイムラインに投稿表示
4. 除外 → 「この投稿はここでは使えません」を表示

### シナリオ2: タイムラインを見る
1. ユーザーがトップページを開く
2. 全ユーザーの「仕事じゃないけど」投稿が時系列で表示される
3. 気に入った投稿にスタンプを押す

### シナリオ3: 自分の投稿を振り返る
1. ユーザーが「自分の投稿」ページを開く
2. 自分の過去投稿一覧とスタンプ数が表示される
