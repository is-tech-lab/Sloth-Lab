## 質問 1 — Unit 2 と Unit 3 の境界

実行計画では Unit 2（Post + AIフィルタリング）と Unit 3（AIコメント生成）を分けています。
ただし、PostService は内部で AIFilteringService と AICommentService を **同じリクエスト内で連続して呼び出す** 設計になっています。

このユニット分割をどうしますか？

A) **分割を維持** — Unit 2（Post + Filtering）と Unit 3（AIComment）は別々のユニットとして開発する。Unit 2 では AIComment 部分を stub/モックで代替し、Unit 3 で本実装に差し替える
B) **Unit 2 + 3 を統合** — PostService のフロー全体（フィルタリング → コメント生成 → 保存）を 1 ユニットとして開発する。Unit 数は 3 に減る（Auth / Post+AI / Feed）
C) Other (その他の場合は [Answer]: タグの後に記述してください)

[Answer]: B

## 質問 3 — タイムライン（Feed）の認証要否

要件・設計では GET /api/feed は認証不要（未ログインでも閲覧可能）としています。
フロントエンドの `/`（タイムラインページ）も同様に未ログインで閲覧できるようにしますか？

A) **未ログインで閲覧可** — トップページのタイムラインは誰でも見られる。投稿・自分の投稿一覧のみログイン必須とする
B) **全ページログイン必須** — ログイン前はすべてのページを `/auth/login` にリダイレクトする
C) Other (その他の場合は [Answer]: タグの後に記述してください)

[Answer]: A

## 質問 4 — ユニット間のコード共有戦略

すべてのユニットが 1 つの Next.js リポジトリを共有します。
共通コード（型定義・DynamoDB クライアント初期化・エラーハンドリングユーティリティ等）の扱いを教えてください。

A) **`lib/` に共通モジュールを集約** — `lib/types/`・`lib/db/`（DynamoDB クライアント）・`lib/utils/` を最初のユニットで作成し、以降のユニットが再利用する
B) **各ユニットで必要なときに追加** — 共通コードは初期化せず、各ユニットのコード生成時に必要な共通コードを都度 `lib/` に追加していく
C) Other (その他の場合は [Answer]: タグの後に記述してください)

[Answer]: A
