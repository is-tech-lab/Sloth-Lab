# エラー処理と復旧手順

## 一般的なエラー処理の原則

### エラーが発生した場合
1. **エラーを特定する**: 何が問題だったかを明確に述べる
2. **影響を評価する**: エラーが処理をブロックするか、回避策があるかを判断する
3. **伝達する**: エラーと選択肢についてユーザーに通知する
4. **解決策を提示する**: 解決または回避するための明確な手順を提供する
5. **記録する**: エラーと解決策を `audit.md` に記録する

### エラーの重大度レベル

**致命的 (Critical)**: ワークフローを継続できない
- 必要なファイルまたは成果物が欠損している
- 処理できない無効なユーザー入力
- ファイル操作を妨げるシステムエラー

**高 (High)**: ステージが計画通りに完了できない
- 必須の質問への回答が不完全
- 矛盾するユーザーの回答
- 前のステージからの依存関係が欠損している

**中 (Medium)**: 回避策を使用してステージを継続できる
- オプションの成果物が欠損している
- 致命的でない検証の失敗
- 部分的な完了が可能

**低 (Low)**: 進行をブロックしない軽微な問題
- フォーマットの不一致
- オプション情報の欠損
- 非ブロッキングの警告

## ステージ別のエラー処理

### ワークスペース検出 (Workspace Detection) のエラー

**エラー**: ワークスペースファイルを読み取れない
- **原因**: 権限の問題、ディレクトリの欠損
- **解決策**: ワークスペースのパスと権限を確認するようユーザーに依頼する
- **回避策**: ユーザーが提供した情報のみで進める

**エラー**: 既存の `aidlc-state.md` が破損している
- **原因**: 手動編集、前回の実行の不完全な終了
- **解決策**: 最初からやり直すか、復旧を試みるかをユーザーに確認する
- **復旧**: バックアップを作成し、新しい状態ファイルを開始する

**エラー**: 必要なステージを決定できない
- **原因**: ユーザーからの情報が不十分
- **解決策**: 意図とスコープに関する確認質問を行う
- **回避策**: 包括的な実行計画をデフォルトとする

### 要件分析 (Requirements Analysis) のエラー

**エラー**: ユーザーが矛盾する要件を提供している
- **原因**: 理解が不明確、ニーズの変化
- **解決策**: 矛盾を解消するためのフォローアップ質問を作成する
- **進めない (Do Not Proceed)**: 矛盾が解消されるまで

**エラー**: 要件ドキュメントを変換できない
- **原因**: サポートされていない形式、破損したファイル
- **解決策**: サポートされている形式で要件を提供するようユーザーに依頼する
- **回避策**: ユーザーの口頭説明で対応する

**エラー**: 検証質問への回答が不完全
- **原因**: ユーザーが質問をスキップした、何を回答すべきか不明
- **解決策**: 未回答の質問を強調表示し、例を提供する
- **進めない (Do Not Proceed)**: すべての必須質問に回答されるまで

### ユーザーストーリー (User Stories) のエラー

**エラー**: 要件をストーリーにマッピングできない
- **原因**: 要件が曖昧すぎる、機能的な詳細が欠落している
- **解決策**: 明確化のために要件分析 (Requirements Analysis) に戻る
- **回避策**: 利用可能な情報に基づいてストーリーを作成し、未完了としてマークする

**エラー**: ユーザーがストーリー計画の回答を曖昧に提供している
- **原因**: 選択肢が不明確、複雑な判断
- **解決策**: 具体的な例を含むフォローアップ質問を追加する
- **進めない (Do Not Proceed)**: 曖昧さが解消されるまで

**エラー**: ストーリー生成計画に未完了のステップがある
- **原因**: 実行が中断された、ステップがスキップされた
- **解決策**: 最初の未完了ステップから再開する
- **復旧**: 完了したステップを確認し、チェックポイントから継続する

### アプリケーション設計 (Application Design) のエラー

**エラー**: アーキテクチャ上の意思決定が不明確または矛盾している
- **原因**: 回答が曖昧、要件が競合している
- **解決策**: 意思決定を明確にするためのフォローアップ質問を追加する
- **進めない (Do Not Proceed)**: 意思決定が明確に文書化されるまで

**エラー**: サービス/ユニットの数を決定できない
- **原因**: 境界に関する情報が不十分
- **解決策**: デプロイ、チーム構成、スケーリングについて具体的な質問をする
- **回避策**: モノリスをデフォルトとし、後で変更できるようにする

### 設計のエラー

**エラー**: ユニット間の依存関係が循環している
- **原因**: 境界の定義が不十分、密結合
- **解決策**: 循環依存関係を特定し、リファクタリングを提案する
- **復旧**: 循環を解消するためにユニット境界を見直す

**エラー**: ユニット設計計画にステップが欠けている
- **原因**: 計画生成が不完全、テンプレートエラー
- **解決策**: すべての必要なステップを含む計画を再生成する
- **復旧**: 欠けているステップを既存の計画に追加する

**エラー**: 設計成果物を生成できない
- **原因**: ユニット情報が欠けている、要件が不明確
- **解決策**: ユニット定義を明確にするためにユニット生成 (Units Generation) に戻る
- **回避策**: 部分的な設計を生成し、ギャップをマークする

### NFR 実装のエラー

**エラー**: テクノロジースタックの選択に互換性がない
- **原因**: 要件が競合している、プラットフォームの制限
- **解決策**: 非互換性を強調し、ユーザーに選択を求める
- **進めない (Do Not Proceed)**: 互換性のある選択が行われるまで

**エラー**: 組織上の制約を満たすことができない
- **原因**: ネットワーク制限、セキュリティポリシー
- **解決策**: 制約を記録し、回避策をユーザーに確認する
- **エスカレーション**: セットアップに人間の介入が必要になる場合がある

**エラー**: NFR 実装のステップで人間のアクションが必要
- **原因**: AI が特定のタスク (ネットワーク設定、認証情報) を実行できない
- **解決策**: **HUMAN TASK** として明確にマークし、手順を提供する
- **待機**: 先に進む前にユーザーの確認を待つ

### コード生成計画のエラー

**エラー**: コード生成計画が不完全
- **原因**: 設計成果物が欠けている、要件が不明確
- **解決策**: 成果物を完成させるために設計ステージに戻る
- **復旧**: 利用可能な情報で計画を生成し、ギャップをマークする

**エラー**: ユニットの依存関係が満たされていない
- **原因**: 依存するユニットがまだ生成されていない
- **解決策**: 依存関係を考慮して生成シーケンスを並び替える
- **回避策**: スタブ依存関係で生成し、後で統合する

### コード生成のエラー (パート 2: コード生成)

**エラー**: ステップのコードを生成できない
- **原因**: 設計情報が不十分、要件が不明確
- **解決策**: ステップをスキップし、未完了として記録し、継続する
- **復旧**: 追加情報を収集した後にステップに戻る

**エラー**: 生成されたコードに構文エラーがある
- **原因**: テンプレートの問題、言語固有の問題
- **解決策**: 構文エラーを修正し、必要に応じて再生成する
- **検証**: 先に進む前にコードがコンパイルされることを確認する

**エラー**: テスト生成が失敗する
- **原因**: 複雑なロジック、テストフレームワークのセットアップが欠けている
- **解決策**: 基本的なテスト構造を生成し、手動で完成するようにマークする
- **回避策**: テストなしで進め、オペレーションズ・フェーズ (OPERATIONS PHASE) で追加する

### オペレーションズ (Operations) のエラー

**エラー**: ビルドツールを特定できない
- **原因**: 特殊なプロジェクト構造、複数のビルドシステム
- **解決策**: ビルドツールとコマンドを指定するようユーザーに依頼する
- **回避策**: 汎用的な手順を提供し、ユーザーが適応する

**エラー**: デプロイ先が不明確
- **原因**: 複数の環境、複雑なインフラ
- **解決策**: デプロイ先と方法を指定するようユーザーに依頼する
- **回避策**: 一般的なプラットフォームの手順を提供する

## 復旧手順

### ステージの部分的な完了

**シナリオ**: ステージが実行の途中で中断された

**復旧ステップ**:
1. ステージの計画ファイルを読み込む
2. 最後に完了したステップ (最後の [x] チェックボックス) を特定する
3. 次の未完了ステップから再開する
4. 前のすべてのステップが実際に完了していることを確認する
5. 通常通り実行を継続する

### 状態ファイルの破損

**シナリオ**: `aidlc-state.md` が破損または不整合な状態

**復旧ステップ**:
1. バックアップを作成する: `aidlc-state.md.backup`
2. ユーザーに実際に進行中のステージを確認する
3. 状態ファイルをゼロから再生成する
4. 既存の成果物に基づいて完了ステージをマークする
5. 現在のステージから再開する

### 成果物の欠損

**シナリオ**: 前のステージからの必要な成果物が欠けている

**復旧ステップ**:
1. 欠けている成果物を特定する
2. 再生成できるかどうかを判断する
3. 可能な場合: そのステージに戻り、成果物を再生成する
4. 不可能な場合: 情報を手動で提供するようユーザーに依頼する
5. ギャップを `audit.md` に記録する

### ユーザーがステージを再実行したい場合

**シナリオ**: ユーザーがステージの結果に満足せず、やり直しを希望する

**復旧ステップ**:
1. ユーザーが再実行を望むことを確認する (データが失われる)
2. 既存の成果物をアーカイブする: `{artifact}.backup`
3. `aidlc-state.md` でステージのステータスをリセットする
4. 計画ファイルのステージのチェックボックスをクリアする
5. 最初からステージを再実行する

### ユーザーがステージをスキップしたい場合

**シナリオ**: ユーザーが計画されているステージをスキップしたい

**復旧ステップ**:
1. ユーザーが影響を理解していることを確認する
2. スキップの理由を `audit.md` に記録する
3. `aidlc-state.md` でステージを「SKIPPED」としてマークする
4. 次のステージに進む
5. 注意: 依存関係が欠けている場合、後のステージで問題が発生する可能性がある

## エスカレーションガイドライン

### ユーザーの助けを求めるタイミング

**即座に**:
- 矛盾または曖昧なユーザー入力
- 必要な情報が欠けている
- AI が解決できない技術的制約
- ビジネス判断を要する意思決定

**解決を試みた後**:
- 同じステップで繰り返しエラーが発生する
- 複雑な技術的問題
- 特殊なプロジェクト構造
- 外部システムとの統合

### やり直しを提案するタイミング

**以下の場合は最初からのやり直しを検討する**:
- 複数のステージでエラーが発生している
- 状態ファイルが深刻に破損している
- ユーザーの要件が大幅に変更されている
- アーキテクチャ上の意思決定を覆す必要がある
- ユーザーが欠けている情報を提供できない
- フェーズをまたいで成果物が一貫していない

**やり直す前に**:
1. 既存のすべての作業をアーカイブする
2. 学んだことを記録する
3. 保持するものを特定する
4. ユーザーの確認を得る
5. 新しい実行計画を作成する

## セッション再開のエラー

### 再開時の成果物の欠損

**エラー**: 前のステージからの必要な成果物が欠けている
- **原因**: ファイルが削除または移動された、または作成されなかった
- **解決策**: 
  1. どのステージが欠けている成果物を作成したかを特定する
  2. `aidlc-state.md` でステージが完了とマークされているか確認する
  3. 完了としてマークされているが成果物が欠けている場合: そのステージを再生成する
  4. 完了としてマークされていない場合: そのステージから再開する
- **復旧**: 欠けている成果物を作成するステージに戻って再実行する

**エラー**: 成果物ファイルは存在するが空または破損している
- **原因**: 書き込みの中断、手動編集、ファイルシステムの問題
- **解決策**:
  1. 破損したファイルのバックアップを作成する
  2. それを作成するステージから再生成を試みる
  3. 再生成できない場合: 情報を再作成するようユーザーに依頼する
- **復旧**: 成果物を作成するステージを再実行する

### 再開時の状態の不一致

**エラー**: `aidlc-state.md` はステージが完了と示しているが成果物が存在しない
- **原因**: 状態ファイルが更新されたが成果物の生成が失敗した
- **解決策**:
  1. `aidlc-state.md` でステージを未完了としてマークする
  2. ステージを再実行して成果物を生成する
  3. 完了とマークする前に成果物が存在することを確認する
- **復旧**: ステージのステータスをリセットして再実行する

**エラー**: 成果物は存在するが `aidlc-state.md` はステージが未完了と示している
- **原因**: 成果物の生成は成功したが状態の更新が失敗した
- **解決策**:
  1. 成果物が完全かつ有効であることを確認する
  2. `aidlc-state.md` を更新してステージを完了としてマークする
  3. 次のステージに進む
- **復旧**: 実際の完了状態を反映するよう状態ファイルを更新する

**エラー**: `aidlc-state.md` に複数のステージが「現在」としてマークされている
- **原因**: 状態ファイルの破損、手動編集
- **解決策**:
  1. 成果物を確認して実際の進行状況を判断する
  2. 実際に進行中のステージをユーザーに確認する
  3. `aidlc-state.md` を修正して単一の現在のステージを示す
- **復旧**: 既存の成果物に基づいて状態ファイルを再構築する

### コンテキスト読み込みのエラー

**エラー**: 前のステージからの必要なコンテキストを読み込めない
- **原因**: ファイルの欠損、コンテンツの破損、ファイルパスの誤り
- **解決策**:
  1. 現在のステージに必要な成果物を一覧表示する
  2. 欠けているまたは破損しているものを確認する
  3. 欠けている成果物を再生成するか、ユーザーに情報を求める
- **復旧**: 現在のステージを再開する前に前提ステージを完了させる

**エラー**: 読み込まれた成果物に矛盾する情報が含まれている
- **原因**: 手動編集、複数人の作業、不完全な更新
- **解決策**:
  1. 矛盾を特定してユーザーに提示する
  2. どの情報が正しいかユーザーに確認する
  3. 矛盾を解消するよう成果物を更新する
- **復旧**: 先に進む前に矛盾を調整する

### 再開のベストプラクティス

1. **常に状態を検証する**: `aidlc-state.md` が実際の成果物と一致することを確認する
2. **段階的に読み込む**: 成果物をステージごとに読み込み、それぞれを検証する
3. **早期に失敗する**: 重要な成果物が欠けている場合はすぐに停止する
4. **明確に伝達する**: 何が欠けているか、なぜ必要かをユーザーに正確に伝える
5. **選択肢を提示する**: 再生成、手動提供、または最初からやり直し
6. **復旧を記録する**: すべての復旧アクションを `audit.md` に記録する

## ログ要件

### エラーログのフォーマット

```markdown
## エラー - [ステージ名]
**タイムスタンプ**: [ISO タイムスタンプ]
**エラータイプ**: [Critical/High/Medium/Low]
**説明**: [何が問題だったか]
**原因**: [なぜ発生したか]
**解決策**: [どのように解決したか]
**影響**: [ワークフローへの影響]

---
```

### 復旧ログのフォーマット

```markdown
## 復旧 - [ステージ名]
**タイムスタンプ**: [ISO タイムスタンプ]
**問題**: [何の復旧が必要だったか]
**復旧ステップ**: [何をしたか]
**結果**: [復旧の結果]
**影響を受けた成果物**: [ファイルの一覧]

---
```

## 予防のベストプラクティス

1. **早期に検証する**: 作業を開始する前に入力と依存関係を確認する
2. **頻繁にチェックポイントを設ける**: ステップを完了した直後にチェックボックスを更新する
3. **明確に伝達する**: 何をしているか、なぜそうするかを説明する
4. **質問する**: 仮定を立てず — 曖昧さはすぐに明確にする
5. **すべてを記録する**: すべての意思決定と変更を `audit.md` に記録する
