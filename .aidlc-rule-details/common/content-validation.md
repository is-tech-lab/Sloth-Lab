# コンテンツ検証ルール

## 必須 (MANDATORY): ファイル作成前のコンテンツ検証

**重要 (CRITICAL)**: 生成されたすべてのコンテンツは、パースエラーを防ぐためにファイルへの書き込み前に検証しなければならない。

## ASCII ダイアグラム標準

**重要 (CRITICAL)**: ASCII ダイアグラムを含むファイルを作成する前に:

1. **読み込む**: `common/ascii-diagram-standards.md` を読み込む
2. **各ダイアグラムを検証する**:
   - 行ごとの文字数を数える (すべての行は同じ幅でなければならない)
   - 使用可能な文字: `+` `-` `|` `^` `v` `<` `>` およびスペースのみ
   - Unicode のボックス描画文字は禁止 (NO)
   - スペースのみ使用 (タブは禁止 (NO))
3. **ボックスの角が縦に揃っていることを確認**してアライメントをテストする

**パターンと検証チェックリストは `common/ascii-diagram-standards.md` を参照すること。**

## Mermaid ダイアグラムの検証

### 必須の検証手順
1. **構文チェック**: ファイル作成前に Mermaid の構文を検証する
2. **文字エスケープ**: 特殊文字が適切にエスケープされていることを確認する
3. **フォールバックコンテンツ**: Mermaid の検証が失敗した場合はテキスト代替を提供する

### Mermaid 検証ルール
```markdown
## Mermaid ダイアグラムを含むファイルを作成する前に:

1. ノード ID に無効な文字がないか確認する (英数字とアンダースコアのみ使用可)
2. ラベル内の特殊文字をエスケープする: " → \" および ' → \'
3. フローチャートの構文を検証する: ノードの接続が有効であること
4. 簡易検証でダイアグラムのパースをテストする

## フォールバック: Mermaid の検証が失敗した場合は、テキストベースのワークフロー表現を使用する
```

### 実装パターン
```markdown
## ワークフローの可視化

### Mermaid ダイアグラム (構文が有効な場合)
```mermaid
[validated diagram content]
```

### テキスト代替 (常に含める)
```
フェーズ 1: INCEPTION
- ステージ 1: ワークスペース検出 (COMPLETED)
- ステージ 2: 要件分析 (COMPLETED)
[テキスト表現を続ける]
```

## 一般的なコンテンツ検証

### 作成前の検証チェックリスト
- [ ] 埋め込みコードブロックを検証する (Mermaid、JSON、YAML)
- [ ] 特殊文字のエスケープを確認する
- [ ] Markdown 構文の正確性を検証する
- [ ] コンテンツのパース互換性をテストする
- [ ] 複雑な要素にはフォールバックコンテンツを含める

### エラー防止ルール
1. **ファイルの書き込みにツール/コマンドを使用する前に必ず検証する**: 未検証のコンテンツを書き込んではならない (禁止 (NEVER))
2. **特殊文字をエスケープする**: 特にダイアグラムとコードブロック内において
3. **代替手段を提供する**: ビジュアルコンテンツのテキスト版を含める
4. **構文を検証する**: 複雑なコンテンツ構造を検証する

## 検証失敗時の処理

### 検証が失敗した場合
1. **エラーを記録する**: 検証に失敗した内容を記録する
2. **フォールバックコンテンツを使用する**: テキストベースの代替手段に切り替える
3. **ワークフローを継続する**: コンテンツ検証の失敗でブロックしない
4. **ユーザーに通知する**: パースの制約によりシンプル化されたコンテンツが使用されたことを伝える
